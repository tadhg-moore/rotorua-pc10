General Lake Model (GLM v4) setup with alum_aed

Author

Tadhg Moore

Published

19 October 2026

Overview

This page documents the General Lake Model (GLM v4) configuration used for simulating the lake’s thermal dynamics, water balance, and nutrient cycling. The model is coupled to the Aquatic EcoDynamics (AED) library for biogeochemical processes.

The AEME package was used to retrieve and format lake characteristics, boundary conditions, and monitoring data for model configuration and validation. The glm4.nml and aed.nml files define the physical and biogeochemical model parameters, respectively, while CSV files provide time series of inflows, meteorological forcing, and phytoplankton parameters.

Note

All simulation configuration files, scripts, and outputs documented here correspond to the baseline run (run_id: aeme_base).

Lake characteristics

Model schematic

The schematic below shows the overall GLM–AED model configuration for Lake Rotorua, including the principal inflows, outflow, atmospheric forcing, and the biogeochemical modules activated in this simulation.

TipSchematic notes
  • Inflows: Four principal inflows are configured (Hamurana, Ohau, Waiowhiro, Waiteti streams). Loads are derived from monitored flow and water quality data (BoPRC).
  • Outflow: The Ohau Channel is the sole surface outflow; weir crest elevation set at 279.38 m a.s.l.
  • Meteorology: Half-hourly data from the Rotorua Airport NIWA station (agent 89894), gap-filled using ERA5 reanalysis where needed.
  • WWTP: Treated effluent from Rotorua WWTP is included as a point-source inflow.
  • AED modules active: NIT (nitrogen), PHO (phosphorus), OGM (organic matter), PHY (phytoplankton).
  • Sediment: 5-zone benthic configuration (benthic_mode = 2); zone-specific oxygen/N/P fluxes and sediment heat-model parameters from measured internal loading data — see the “Sediment zones” tab below.

```{r setup}
#| include: false
#| echo: false
library(dplyr)
library(ggplot2)
library(scales)
library(patchwork)
library(AEME)
library(knitr)
library(kableExtra)
library(targets)

source("../R/plot_aeme_loads.R")
source("../R/setup_base_aeme.R")
source("../R/scenario_climate_workflow.R")

glm_ver <- get_model_version("glm_aed")
glm_version <- regmatches(glm_ver[1], regexpr("\\d+\\.\\d+\\.\\d+", glm_ver[1]))

# Baseline (run_id: aeme_base) is a historical run, so scenario = "historical".
# GCM choice still matters for it, since the met forcing is downscaled CMIP6
# historical output, not observations — ACCESS-CM2 (cmip_gcm[1]) is used as
# the reference GCM for this documentation page; change if a different GCM
# should represent the baseline.
path <- "glm_v4"
model <- targets::tar_read(model)
# aeme <- setup_base_aeme(path = path)
aeme <- readRDS("../LID11133_rotorua/aeme_download.rds")

# Meteorology: switch from the daily forcing to the processed hourly ERA5
# series (data/processed/rotorua_era5_hourly.csv) — build_aeme()/build_glm()
# detect the sub-daily timestep and set &meteorology/subdaily accordingly.
lake_meta <- AEME::lake(aeme)
era5_met <- read_era5_hourly_met("../data/processed/rotorua_era5_hourly.csv",
                                  lat = lake_meta$latitude,
                                  lon = lake_meta$longitude)

corr_hyps <- targets::tar_read(corr_hyps)
hyps_no_hole <- targets::tar_read(hyps_no_hole)
hyps_adj <- min(hyps_no_hole$elev) - min(corr_hyps$elev)

# AED calibration parameter set from the sensitivity-analysis screening csv.
# aed_sed_const2d/* rows are applied automatically by build_aeme() via
# set_aed_sed_const2d(); every other aed.nml/aed_phyto_pars.csv row is
# written by hand below once the config files exist on disk.
calib_params <- readr::read_csv("../data/aed/aed_sa_calib_params.csv",
                                 show_col_types = FALSE)

# Measured 5-zone sediment configuration from the _targets.R calibration
# pipeline (targets: zone_heights, glm_sed_param_meas, meas_param) — read via
# targets::tar_read() so this page always reflects whatever is currently
# committed to the pipeline instead of a copy that can drift out of sync.
# `glm_sed_param_meas` (built from `zone_heights`) sets up the GLM &sediment
# zone structure itself (n_zones, zone_heights, sed_heat_Ksoil, ...);
# `meas_param` overrides it with the measured sed_temp/sed_vwc/aed_sed_const2d
# values (Kaylee Campbell internal loading study) for each of the 5 zones.
# Both "sediment/*" and "aed_sed_const2d/*" rows are applied automatically by
# build_aeme() below; the handful of scalar aed.nml rows (Ksed_oxy, etc.) are
# written by hand alongside calib_params further down.
zone_heights <- targets::tar_read(zone_heights)
zone_heights <- zone_heights[-1] - hyps_adj
glm_sed_param_meas <- targets::tar_read(glm_sed_param_meas)
AEME::glm_sed_params(n_zones = length(zone_heights), zone_heights = zone_heights)
meas_param <- targets::tar_read(meas_param)

meas_param |> 
  dplyr::filter(file == "aed.nml" & grepl("^aed_sed_const2d/fsed_", name)) |>
  dplyr::select(file, name, index, value) |>
  dplyr::arrange(name, index)

all_param <- dplyr::bind_rows(meas_param, glm_sed_param_meas) |> 
  dplyr::anti_join(calib_params, by = c("file", "name", "index"))

dups <- all_param |> 
  dplyr::group_by(file, name, index) |>
  dplyr::summarise(n = dplyr::n(), .groups = "drop") |>
  dplyr::filter(n > 1)


aeme <- aeme |>
  AEME::remove_param() |> 
  AEME::add_met(era5_met) |> 
  AEME::add_hypsograph(hyps_no_hole) |> 
  AEME::add_param(all_param) 

lake_dir <- AEME::get_lake_dir(aeme)

aed_file <- file.path(lake_dir, "glm_aed", "aed", "aed.nml")
phyto_file <- file.path(lake_dir, "glm_aed", "aed", "aed_phyto_pars.csv")

aed_nml_obj <- AEME::read_nml(aed_file)
# Disable N2O simulation (aed_nitrogen/simn2o: 2 -> 0).
aed_nml_obj[["aed_nitrogen"]][["simn2o"]] <- 0

AEME::write_nml(aed_nml_obj, file = aed_file)

cfg <- configuration(aeme)
glm4_nml <- cfg[["glm_aed"]][["hydrodynamic"]]
# Re-read aed.nml rather than using cfg$glm_aed$bgc$aed, since that slot was
# populated by build_aeme() before the calibration-parameter/simn2o edits
# above were written to the file.
aed_nml <- AEME::read_nml(aed_file)

phyto_cols <- aed_nml$aed_phytoplankton$the_phytos + 1

inflows <- get_inflows(aeme)
inflow_humurana <- inflows[["Hamurana"]]

met <- readr::read_csv(file.path(lake_dir, "glm_aed", "bcs", "meteo_glm.csv"))
phyto_pars <- AEME::read_aed_param_csv(phyto_file)
phyto_pars <- phyto_pars[, c(1, phyto_cols)]

sim_period <- AEME::suggest_sim_period(aeme)

aeme <- tar_read(aeme_baseline)

aeme <- aeme |>
  # AEME::set_sim_period(sim_period) |> 
  build_aeme(path = path, use_bgc = TRUE) |>
  run_aeme(extra_vars = "all")


# Model performance
aeme_time <- time(aeme)
period <- paste0(format(aeme_time$start, "%Y"), "–", format(aeme_time$stop, "%Y"))

perf <- assess_aeme(aeme, var_sim = c("HYD_temp", "LKE_lvlwtr")) |> 
  dplyr::mutate(Period = period) |>
  dplyr::rename(Variable = name_text, RMSE = rmse, Bias = bias, R2 = rs) |> 
  dplyr::select(Variable, Period, RMSE, Bias, R2, n)

```

## Overview {#overview}

This page documents the **General Lake Model (GLM v4)** configuration used for simulating the lake's thermal dynamics, water balance, and nutrient cycling. The model is coupled to the **Aquatic EcoDynamics (AED)** library for biogeochemical processes.

The [AEME](https://limnotrack.com/AEME/) package was used to retrieve and format lake characteristics, boundary conditions, and monitoring data for model configuration and validation. The `glm4.nml` and `aed.nml` files define the physical and biogeochemical model parameters, respectively, while CSV files provide time series of inflows, meteorological forcing, and phytoplankton parameters.

::: {.callout-note}
All simulation configuration files, scripts, and outputs documented here correspond to the
**baseline run** (`run_id: aeme_base`). 
:::
