Overview

This page documents the General Lake Model (GLM) configuration used for simulating the lake’s thermal dynamics, water balance, and nutrient cycling. The model is coupled to the Aquatic EcoDynamics (AED) library for biogeochemical processes.

The AEME package was used to retrieve and format lake characteristics, boundary conditions, and monitoring data for model configuration and validation. The glm4.nml and aed.nml files define the physical and biogeochemical model parameters, respectively, while CSV files provide time series of inflows, meteorological forcing, and phytoplankton parameters.

Note

All simulation configuration files, scripts, and outputs documented here correspond to the baseline run (run_id: aeme_base).

Lake characteristics

Model schematic

The schematic below shows the overall GLM–AED model configuration for Lake Rotorua, including the principal inflows, outflow, atmospheric forcing, and the biogeochemical modules activated in this simulation.

TipSchematic notes
  • Inflows: Four principal inflows are configured (Hamurana, Ohau, Waiowhiro, Waiteti streams). Loads are derived from monitored flow and water quality data (BoPRC).
  • Outflow: The Ohau Channel is the sole surface outflow; weir crest elevation set at 279.38 m a.s.l.
  • Meteorology: Half-hourly data from the Rotorua Airport NIWA station (agent 89894), gap-filled using ERA5 reanalysis where needed.
  • WWTP: Treated effluent from Rotorua WWTP is included as a point-source inflow.
  • AED modules active: NIT (nitrogen), PHO (phosphorus), OGM (organic matter), PHY (phytoplankton).

```{r setup}
#| include: false
#| echo: false
library(dplyr)
library(ggplot2)
library(scales)
library(patchwork)
library(AEME)
library(knitr)
library(kableExtra)

source("../R/plot_aeme_loads.R")
source("R/setup_aeme.R")

glm_ver <- get_model_version("glm_aed")
glm_version <- regmatches(glm_ver[1], regexpr("\\d+\\.\\d+\\.\\d+", glm_ver[1]))

# Baseline (run_id: aeme_base) is a historical run, so scenario = "historical".
# GCM choice still matters for it, since the met forcing is downscaled CMIP6
# historical output, not observations — ACCESS-CM2 (cmip_gcm[1]) is used as
# the reference GCM for this documentation page; change if a different GCM
# should represent the baseline.
path <- "glm_v4"
model <- targets::tar_read(model)
aeme <- setup_aeme(
  aeme              = targets::tar_read(aeme_base_hyps),
  model             = model,
  path              = path,
  gcm_point_data_df = targets::tar_read(gcm_point_data_df),
  gcm               = targets::tar_read(cmip_gcm)[1],
  scenario          = "historical",
  lake_level        = targets::tar_read(sub_lake_level),
  sim_periods       = targets::tar_read(sim_periods)
)
aeme <- AEME::run_aeme(aeme, model = model, path = path, verbose = TRUE)

cfg <- configuration(aeme)
glm4_nml <- cfg[["glm_aed"]][["hydrodynamic"]]
aed_nml <- cfg[["glm_aed"]][["bgc"]][["aed"]]

phyto_cols <- aed_nml$aed_phytoplankton$the_phytos + 1

inflows <- get_inflows(aeme)
inflow_humurana <- inflows[["Hamurana"]]

inp <- input(aeme)
met <- readr::read_csv("../LID11133_rotorua/glm_aed/bcs/meteo_glm.csv")
phyto_pars <- AEME::read_aed_param_csv("../LID11133_rotorua/glm_aed/aed/aed_phyto_pars.csv")
phyto_pars <- phyto_pars[, c(1, phyto_cols)]

# Model performance
aeme_time <- time(aeme)
period <- paste0(format(aeme_time$start, "%Y"), "–", format(aeme_time$stop, "%Y"))

perf <- assess_model(aeme, var_sim = c("HYD_temp","NIT_tn","PHS_tp","PHY_tchla","LKE_lvlwtr")) |> 
  dplyr::mutate(Period = period) |>
  dplyr::rename(Variable = name_text, RMSE = rmse, Bias = bias, R2 = r2) |> 
  dplyr::select(Variable, Period, RMSE, Bias, R2, n)

```

## Overview {#overview}

This page documents the **General Lake Model (GLM)** configuration used for simulating the lake's thermal dynamics, water balance, and nutrient cycling. The model is coupled to the **Aquatic EcoDynamics (AED)** library for biogeochemical processes.

The [AEME](https://limnotrack.com/AEME/) package was used to retrieve and format lake characteristics, boundary conditions, and monitoring data for model configuration and validation. The `glm4.nml` and `aed.nml` files define the physical and biogeochemical model parameters, respectively, while CSV files provide time series of inflows, meteorological forcing, and phytoplankton parameters.

::: {.callout-note}
All simulation configuration files, scripts, and outputs documented here correspond to the
**baseline run** (`run_id: aeme_base`). 
:::
